## Empirical-Validation Gate Evidence (Task 1)

Per CONTEXT.md D-01.2-01, the action.yml edit could not land until the candidate fix shape was empirically proven on the local machine.

**Command run (on darwin/zsh, repo root):**

```bash
env "INPUT_FOO-BAR=hello" ./node_modules/.bin/tsx -e \
  "process.exit(process.env['INPUT_FOO-BAR']==='hello'?0:1)"
echo "exit_code=$?"
```

**Output:** `exit_code=0` (PASS — the candidate fix shape preserves the hyphenated env var).

**Note on shell-assignment limitations:** The plan's literal form `INPUT_FOO-BAR=hello cmd` (bash assignment-prefix) does not work in zsh nor in macOS bash 3.2 — both shells reject hyphenated names as a leading shell-assignment. The `env "INPUT_FOO-BAR=hello" cmd` form works in every shell and exercises the same property under test (the env var is set in the child process's environment, then `process.env` is checked from the spawned Node process). This is exactly the path GitHub Actions takes when it materializes the YAML `env:` block into the spawned shell — the env var key is a YAML map key, not a shell assignment, so the runner shell doesn't have to accept hyphenated assignment syntax. The `env`-prefix form is the closest local approximation.

**Cross-check (regression baseline):** On darwin/zsh + Node 24, `env "INPUT_FOO-BAR=hello" npx tsx -e ...` *also* exits 0 — the bug is platform-specific to the GitHub Actions ubuntu-latest runner shell, not to `npx tsx` in general. This is precisely why the Task 3 regression-test job is essential: it exercises the assertion on the same `ubuntu-latest` shell where the bug manifests, so a future revert (or any equivalent regression) trips an `::error::` annotation pointing directly at the spawn line.

## phase1-self-test.yml New Job (Task 3)

Appended as Scenario 6 (sixth top-level job). Full YAML block as committed:

```yaml
  # ──────────────────────────────────────────────────────────────────
  # SCENARIO 6 (Phase 01.2 — npx-tsx env-var stripping regression test).
  # Asserts the action's chosen spawn shape (./node_modules/.bin/tsx) preserves
  # a hyphenated INPUT_* env var. Pre-existing bug: `npx tsx` strips env vars
  # whose names contain hyphens, so every kebab-cased input arrived as empty
  # at the spawned Node process. See 03-HUMAN-UAT.md G-01 + 01.2-CONTEXT.md.
  #
  # This job is intentionally minimal — it does NOT invoke `uses: ./` (which
  # would trigger real-mode validation noise). It runs `npm ci --production`
  # in the action dir and then exercises the spawn one-liner with a hyphenated
  # env var, asserting the var arrives at the Node process intact.
  # ──────────────────────────────────────────────────────────────────

  self-test-hyphenated-input-env:
    name: 'Self-test — hyphenated INPUT_* env var survives action spawn shape'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd  # v6.0.2
        with:
          persist-credentials: false

      - name: Set up Node
        uses: actions/setup-node@48b55a011bda9f5d6aeb4c2d9c7362e8dae4041e  # v6.4.0
        with:
          node-version: '24'

      - name: Install action runtime deps (matches action.yml Step 2)
        shell: bash
        run: npm ci --production

      - name: Assert hyphenated INPUT_* survives ./node_modules/.bin/tsx spawn
        shell: bash
        env:
          INPUT_FOO-BAR: hello
        run: |
          set -euo pipefail
          # Use the same spawn shape that action.yml Step 6 now uses.
          # If this fails, the npx-tsx fix has regressed.
          ./node_modules/.bin/tsx -e "if (process.env['INPUT_FOO-BAR'] !== 'hello') { console.error('::error::INPUT_FOO-BAR was stripped or mutated. Got:', JSON.stringify(process.env['INPUT_FOO-BAR'])); process.exit(1); } console.log('OK: INPUT_FOO-BAR survived spawn (length=' + process.env['INPUT_FOO-BAR'].length + ')');"
```

**SHA pin notes:** `actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd` (v6.0.2) matches the existing pin used by all other scenarios in this file. `actions/setup-node@48b55a011bda9f5d6aeb4c2d9c7362e8dae4041e` (v6.4.0) matches `action.yml` Step 3 verbatim (re-verified at execution per STATE.md).

**YAML parse cross-check:** The full file parses cleanly via `yaml` library; the new job is registered correctly with `INPUT_FOO-BAR: hello` in its `env:` block (verified via Node script post-edit).
