## Phase 04 Hardening Items (NEW failure modes surfaced)

Six items surfaced during execution that should be tracked as Phase 04 hardening:

1. **action.yml Step 1 `clean: true` collides with subpath-checkout consumers** (resolved at i3 with `clean: false`)
   - The CONTEXT D-04 fallback pattern (subpath checkout of action repo) only works if the action's own first checkout step preserves untracked dirs. Without `clean: false`, `.healer/` gets wiped before Step 2.

2. **CLAUDE.md default model `gemini-2.5-pro` is NOT free-tier eligible** (resolved at i4 with `model: gemini-2.5-flash` in fixture workflow)
   - Phase 04 should document the free-tier quota structure and consider making `gemini-2.5-flash` the default for non-billed projects, or at least add deployment guidance.

3. **fix-applier `git add -A` swept untracked files into commit** (resolved at i5 with `git apply --3way --index`)
   - The previous code committed any untracked file in the workspace at commit time. The new code stages exactly what the patch touches.

4. **fix-applier push lacked force flag — re-dispatch idempotency** (resolved at i6→i7→i8 by trying `--force-with-lease` then plain `--force`)
   - Branch names are deterministic (`<testSlug>-<shortSha>`); every re-dispatch reuses the same branch. The original code had no force flag and was rejected on every re-dispatch.

5. **fix-applier `--3way` fetch-depth warning** (non-fatal in i6 — `repository lacks the necessary blob to perform 3-way merge`)
   - The action's workspace is shallow-cloned (`fetch-depth: 1` in sc1-healer.yml). When the patch's index hashes reference blobs not in the shallow clone, `--3way` falls back to a non-3-way apply with a warning. Consider deepening `git fetch --depth=50` in fix-applier or making it conditional on patch index hashes.

6. **`--force-with-lease` requires fetch-of-target in shallow clones** (resolved by switching to plain `--force`)
   - If the namespace ever becomes shared with humans (e.g., maintainer pushes a manual override on a healer branch), reconsider lease — but it requires pre-fetching the heal branch into the local clone.

**Additional non-blocking observation:** The orchestrator's failure-fallback path (`fileIssue` for pipeline-error) hit HTTP 403 in iterations 4-8 — HEALER_PAT lacks `Issues: write` permission on the fixture repo. This doesn't block the happy path (PR creation works), but breaks the failure-mode-routing UX. Phase 04 should either (a) require `Issues: write` in PAT documentation, or (b) make the fileIssue call best-effort (already a `core.warning`, just confirm).

## Authentication Gates (resolved during execution)

Two human-action gates fired during execution and were resolved by user input:

1. **Task 1 — GitHub Settings UI toggle on `Sacharified/playwright-healer`** — user replied `settings-applied`. The API still reported `access_level: "none"` afterward, and iteration 1 did fail with `repository not found` — but rather than re-engage with the Settings UI, we used the subpath-checkout fallback (D-04 explicitly documented), which works regardless. The Settings UI mechanism for personal-account repos may differ from what the API endpoint exposes.

2. **HEALER_PAT scope** — pre-flight Task 2 confirmed the LOCAL `gh auth` token has `repo`+`workflow` (which it did), but did NOT verify the *fixture-repo secret* HEALER_PAT (which is opaque by design). Iteration 2's HTTP 403 surfaced that HEALER_PAT was a fine-grained PAT scoped only to `playwright-healer-test`. User expanded scope (option-b at iteration-2 checkpoint).

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `src/index.ts` not wiring skip-* inputs through `core.getInput()`**
- **Found during:** Task 4 pre-dispatch verification
- **Issue:** Plan 01 added `skipDeterministicCheck`/`skipPostFixValidation`/`skipDiffLint` to the Zod config schema. Plan 02 added the inputs to `action.yml` and mapped `INPUT_SKIP-*` env vars in Step 6. But `src/index.ts`'s `actionInputs` object never called `core.getInput()` for the three flag names, so Zod always saw the schema default `'false'`. Without this wire, CRACK-1 would still fire and the demo would file a deterministic-failure issue instead of a PR.
- **Fix:** Added 3 `core.getInput()` calls + 3 fields to the `actionInputs` object in `src/index.ts`.
- **Files modified:** `src/index.ts`
- **Commit:** `10c8949`
