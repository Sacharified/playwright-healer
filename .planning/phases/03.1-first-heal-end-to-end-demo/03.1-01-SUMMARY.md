# Phase 03.1 Plan 01: Skip Flags + BaseUrl Interpolation Summary

Three demo-mode skip flags added to config schema and threaded through the orchestrator, plus CRACK-4 fixed by wiring `baseUrl` into the `{{BASE_URL}}` placeholder in the selectors prompt template.

## What Was Built

### `src/shared/config.ts`
Three new Zod fields added after the CFG-04 toggles block, following the same `z.string().default('false').transform(v => v === 'true')` pattern (default-OFF, opposite of CFG-04's default-ON toggles):

### `src/healer/index.ts`
Four surgical changes:
1. **Step 4**: `if (!config.skipDeterministicCheck && sanity.passRate === 0)` — gate is now opt-out
2. **Step 5**: `baseUrl: config.baseUrl` added to `assemblePrompt()` call
3. **Step 8**: `if (!config.skipDiffLint && findings.length > 0)` — gate is now opt-out
4. **Step 10**: Replaced inline `validate()` call with a branching block — when `skipPostFixValidation` is true, assigns a sentinel `ValidationResult { passed: 0, total: 0, passRate: 1, perRun: [] }` to the `validation` variable so Step 11's `openHealerPr({ ..., validation })` always receives a fully-formed object. ### Design Note: Sentinel passRate value

The plan specifies `{ passed: 0, total: 0, passRate: 1, perRun: [] }` as the sentinel. With `passRate: 1`, `pr-writer.ts` renders "100%" in the PR body (from `(validation.passRate * 100).toFixed(0)`). The PR body also shows `0/0 reruns at --retries=0`, which makes it clear validation was skipped in demo mode. This is the intended behavior — CI on the PR branch is the truth, not local validation. No action taken; documented here for transparency.
