<objective>
Fix three pre-existing test-design bugs in `.github/workflows/phase1-self-test.yml` that were unmasked by Phase 01.2's spawn-shape fix. The bugs are all latent-since-Phase-01: (1) Scenarios 4 + 5 assume `$GITHUB_STEP_SUMMARY` is job-wide but it is per-step (Pattern 3 in RESEARCH); (2) Scenario 1's TWO-JOB canary-mask pattern relies on `core.setSecret()` masking literal `with: api-key:` values that the runner emits in the step header BEFORE any action body code runs (Pattern 4 in RESEARCH — masking is non-retroactive).

Resolution shape (locked by ROADMAP SC#1–SC#4 + RESEARCH primary recommendation):
- SC#1: `src/index.ts` `runDryRun` calls `core.setOutput('dryRunSummary', md)` after the existing `core.summary.addRaw(md).write()`. `action.yml` declares a top-level `outputs:` block mapping `dry-run-summary` to `${{ steps.run-playwright-healer.outputs.dryRunSummary }}` and adds `id: run-playwright-healer` to Step 6. Scenarios 4 + 5 read the markdown from the composite-action output via `env: SUMMARY: ${{ steps.run.outputs.dry-run-summary }}` and grep on `$SUMMARY` (Pitfall 1 mitigation: env-var indirection escapes backticks/pipes in the markdown).
- SC#2 option (a): Scenario 1 Job A inserts a "Pre-register canary with runner masker" step running `echo "::add-mask::test-canary-DO-NOT-USE-REAL-KEY"` BEFORE `uses: ./`. Comment block above documents the trade-off (verifies the runner masker — the actually-effective control for `with:` values — but does NOT directly verify `core.setSecret()`; that contract is verified by Scenario 4's redacted-markdown grep instead). Option (b) was rejected per RESEARCH §Pattern 4 "Why option (b) has hidden cost" — it would require emitting a redacted-secret log line on every production run.
