## Sampling Rate

- **After every task commit:** Run `npx vitest run --reporter=dot` (locally) — fast confirmation that no production-code regressions in `src/index.ts` runDryRun
- **After every plan wave:** Run `npx vitest run` (full suite, locally)
- **Before `/gsd-verify-work`:** Full local suite green AND a fresh push to GitHub triggers `phase1-self-test.yml` and all six scenarios + the `self-test-hyphenated-input-env` regression job pass on ubuntu-latest
- **Max feedback latency:** ~5 s local, ~3-5 min remote (CI run)

> The authoritative validation surface for this phase is the **live ubuntu-latest run** of `.github/workflows/phase1-self-test.yml`. Local unit tests cannot reproduce the runner's step-header emission timing, the per-step `$GITHUB_STEP_SUMMARY` semantics, or the `::add-mask::` registration order — those were the blind spots that hid the bugs in the first place. The planner MUST design a verification step that includes a real CI run.
