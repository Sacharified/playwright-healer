<decisions>
## Implementation Decisions

### Public input contract

- **D-01:** Hard cutover. `provider: anthropic` and `provider: gemini` are removed from `ProviderEnum` with no alias and no bespoke error message. Pre-release software, no external consumers; one-time migration is acceptable. Workflows passing the removed values will fail at parse time with the standard Zod enum error (which names the field and lists the allowed values). No `core.warning` emitted, no transparent rewrite.
- **D-02:** Default `provider` is `openrouter`. Default model when `model` is empty is `anthropic/claude-sonnet-4.6` (the OpenRouter slug — dot, not hyphen). This preserves the existing "leave it blank, get Claude Sonnet" mental model from Phase 01.1. `config.ts`: `provider: ProviderEnum.default('openrouter')`.

### Self-test surface (`.github/workflows/phase1-self-test.yml`)

- **D-03:** Scenario 4 (`self-test-dry-run`): rewrite the dry-run-summary row assertion from `| provider | anthropic |` to `| provider | openrouter |` + `| model | anthropic/claude-sonnet-4.6 |`. Scenario 5 (`self-test-ollama-empty-key`) stays unchanged — still load-bearing for the per-provider `superRefine` gate. No new openrouter-specific scenarios are added; unit-test coverage in `openrouter.test.ts` (22 tests) plus the manual real-API smoke test run on 2026-05-05 against `anthropic/claude-sonnet-4.6` and `google/gemini-2.5-pro` cover the API contract.

### Commit shape

- **D-04:** Single implementation commit. The additive work currently staged on disk (openrouter.ts + tests + 5-wide ProviderEnum + selectAdapter wiring + four contract corrections from real-API verification) bundles together with the destructive work (gemini deletion, enum narrowing, default change, dependency drop, self-test rewrite, planning-doc updates) into one `feat(01.4): consolidate cloud adapters via OpenRouter` commit. CONTEXT.md + DISCUSSION-LOG.md commit separately as the standard `docs(01.4): capture phase context` planning commit.
- **D-05:** Defer `openai-compat.ts` shared-helper extraction (deduplicating `github.ts` and `openrouter.ts`) to follow-up Phase 01.5. The advisor flagged premature-abstraction risk; doing it after 01.4 lands keeps the destructive cleanup focused. ~80 LOC of duplication between the two adapters is the cost of waiting.

- Whether to keep `anthropic` / `gemini` mentioned in the security-contract.ts doc-comment block as historical context vs deleting those provider rows entirely. Either is fine.
- README provider-table format (markdown table vs prose).

## Existing Code Insights

### Reusable Assets

- **`src/healer/adapters/github.ts`** (369 LOC) — the OpenAI-compatible adapter pattern. `openrouter.ts` mirrors its structure exactly: `Stdio` MCP transport, `Client` connect, `listTools` audit, OpenAI message shape, `tool_calls`-driven loop, `parseFinalText` for FixProposal/NoFixProposable. ~80 LOC of structural duplication remains until Phase 01.5 extracts `openai-compat.ts`.
- **`src/shared/security-contract.ts`** — `ALLOWED_TOOLS`, `MCP_PLAYWRIGHT_TOOL_PREFIX`, `ALLOWED_ORIGIN_TEMPLATE`. All adapters (github, openrouter, ollama-future) consume these unchanged. D-13 inline-literal ban applies.
- **`src/healer/budget.ts`** — `BudgetExhausted` error class is provider-agnostic and stays. The `BudgetTracker` class + Gemini pricing constants are Gemini-only and get deleted.

### Established Patterns

- **Manual MCP tool-use loop** — Both adapters spawn `@playwright/mcp@0.0.70` via `StdioClientTransport`, `mcpClient.connect()`, `listTools()`, then loop `chat/completions` calls dispatching `tool_calls` to `mcpClient.callTool()`. This is the load-bearing shape; do not deviate.
- **SEC-04 audit invariant** — Before the loop starts, every tool returned by `listTools()` must have its canonical form (`mcp__playwright__<name>`) match an `ALLOWED_TOOLS` glob AND its raw name must start with `MCP_PLAYWRIGHT_TOOL_PREFIX`. Throws pre-fetch on violation. `openrouter.ts` already implements this identically.
- **Budget gating** — `BudgetExhausted` thrown pre-fetch at top of each loop iteration. `openrouter.ts` checks both `usdSpent >= maxBudgetUsd` and `turnsUsed >= maxTurns`; `github.ts` checks only `maxTurns` (free-tier zero cost).
- **`{ proposal, stats }` return contract** — Every adapter returns `AgentRunStats { usdSpent, turnsUsed }` populated on every successful path. Orchestrator threads `stats.usdSpent` into PR body PRI-02 cost line.
- **Constructor injection for testability** — `_Client`, `_StdioClientTransport`, `_fetch` opts allow vitest to mock without module-level state.

### Integration Points

- `src/healer/index.ts` `selectAdapter()` (lines ~57–95 after additive change) — provider switch is the only orchestrator-level integration point. 01.4 narrows from 5 cases (gemini, github, openrouter, anthropic stub, ollama stub) to 3 (openrouter, github, ollama stub).
- `src/shared/config.ts` `ProviderEnum`, `DEFAULT_MODELS`, `DEFAULT_ENDPOINTS` — 01.4 narrows enum to 3 entries; removes `anthropic` and `gemini` from both lookup maps.
- `package.json` dependencies — drop `@google/genai`. Confirm no other src file imports it (audit before deletion).
- `.github/workflows/phase1-self-test.yml` scenario 4 step `Verify summary contents` — `provider: anthropic` row assertion → `provider: openrouter` + `model: anthropic/claude-sonnet-4.6` rows.

<specifics>
## Specific Ideas

- **OpenRouter slug convention** — `anthropic/claude-sonnet-4.6` (DOT, not hyphen) is verified against the OpenRouter model catalog and a successful real-API call on 2026-05-05. The Anthropic SDK uses `claude-sonnet-4-6` (hyphen); these MUST NOT be confused. config.ts comment block already documents this distinction.
- **Real-API verification done 2026-05-05:** Both empirical gates flagged in the source plan have passed against the live OpenRouter API.
  - Gate 1 (`usage.cost` field present): Anthropic returned $0.000117, Gemini returned $0.000135, both as JSON `number`.
  - Gate 2 (`tool_calls` shape uniformity): identical outer keys `[function, id, index, type]`, identical `function` keys `[arguments, name]`, `function.arguments` is JSON `string` on both upstreams. The `index` field is extra (not in our `OpenAiToolCall` interface) but TypeScript is structural — it's silently ignored.
- **Contract corrections already applied** to `openrouter.ts` after the real-API verification: removed deprecated `usage: { include: true }` opt-in; cost field is `usage.cost` (not `usage.total_cost`); attribution header is `X-OpenRouter-Title` (not `X-Title`).
- **Self-test surface preserved** — Scenario 5 (`self-test-ollama-empty-key`) stays unchanged. It is the load-bearing CI proof that the per-provider `superRefine` gate did not regress when the enum changed. Do not delete or modify.

</specifics>
