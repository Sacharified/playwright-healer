  ],

  ],

  ]

Followed by exactly one trailing newline (`\n`). The file MUST NOT use tabs, CRLF, or any other formatting — the CI snapshot-diff in Plan 05 compares byte-equality after canonicalization.

**To generate the JSON deterministically** (recommended approach — record this in the SUMMARY so future changes use the same recipe):

```bash
node --input-type=module -e "
const obj = {
  allowedOriginTemplate: ['<baseUrl>', 'http://localhost:*'],
  allowedTools: ['Glob', 'Grep', 'Read', 'mcp__playwright__*'],
  forbiddenWorkflowTriggers: ['pull_request_target'],
};
const canonical = (o) => Array.isArray(o)
  ? [...o].sort()
  : typeof o === 'object' && o !== null
    ? Object.keys(o).sort().reduce((a, k) => { a[k] = canonical(o[k]); return a; }, {})
    : o;
const json = JSON.stringify(canonical(obj), null, 2) + '\n';
process.stdout.write(json);
" > .planning/security-contract.snapshot.json
```

**Critical non-obvious requirements:**

For `security-contract.ts`:

  - Header comment is PART OF THE CONTRACT (PATTERNS item 1). The two-step change protocol must be documented in the file, word-for-word as above.
  - `Object.freeze(...) as const` dual layering (PATTERNS item 2): `as const` narrows TS types to literal tuple; `Object.freeze` enforces runtime immutability. Both required.
  - `ALLOWED_ORIGIN_TEMPLATE` is a function because it depends on runtime `baseUrl`; the RETURNED array is frozen. That's sufficient — immutability applies to the consumed value.
  - Arrays sorted alphabetically (advisor decision, per PATTERNS §4 reconciliation). This makes CI diff simple byte-compare — no array sorting in the lint script needed.
  - Do NOT compute values at module load (no `process.env`, no string concatenation of hostnames). Constants only.

For `security-contract.snapshot.json`:

  - Must NOT be formatted by Prettier, VSCode, or any editor auto-format — use the node one-liner above or paste the literal bytes. Editor formatters produce phantom diffs.
  - Arrays AND top-level keys both alphabetically sorted.
  - The `<baseUrl>` literal placeholder is NOT a URL — it's a parameterization marker (PATTERNS item 3).

```typescript
import { z } from 'zod';

const ModeEnum = z.enum(['ingest', 'heal', 'dry-run'])
  .describe('mode must be one of: ingest, heal, dry-run');

// Factory form: lets tests override defaults without module-level state.
// This is deliberate — matches the D-19 "presence-only in Phase 1, scope checks deferred"
// contract because the schema stays pure.
export function getInputSchema() {
  return z.object({
    mode:            ModeEnum,
    setupCommand:    z.string().default(''),
    startCommand:    z.string().default(''),
    testCommand:     z.string().default(''),
    baseUrl:         z.string().default(''),
    anthropicApiKey: z.string().min(1, { message: 'anthropic-api-key is required and must be non-empty' }),
    healerToken:     z.string().min(1, { message: 'healer-token is required and must be non-empty' }),
    githubToken:     z.string().min(1, { message: 'github-token is required and must be non-empty' }),
  });
}

export type Config = z.infer<ReturnType<typeof getInputSchema>>;
```

**Critical non-obvious requirements** (PATTERNS.md items 1-5):

  1. **Factory function `getInputSchema()`** — NOT a module-level const. Lets tests override defaults without shared module state. Matches D-19's "presence-only in Phase 1" contract.
  2. **`z.string().min(1, { message: ... })` for required secrets** — bare `z.string()` ACCEPTS empty strings. `.min(1)` catches the empty-secret case that SC#4 requires (Phase 06 self-test will invoke with empty `anthropic-api-key` and assert the error message names the field).
  3. **Non-secret optional inputs use `.default('')`** — CFG-01 declares `setup-command`, `start-command`, `test-command`, `base-url` in action.yml; Phase 1 doesn't consume them; default-empty prevents validation failure when caller omits.
  4. **`z.infer<ReturnType<typeof getInputSchema>>`** — exports the inferred `Config` type for downstream modules (dispatcher + stubs + future ingest/heal code).
  5. **Error path names** — rely on `issue.path.join('.')` in the dispatcher (Plan 03). Zod's default produces `mode`, `anthropicApiKey`, etc. The dispatcher formats these. SC#4 requires the error for invalid `mode` to NAME the field; this schema + dispatcher formatting satisfies that.

**What NOT to do:**
  - Do NOT split the schema across multiple files (CONTEXT Claude's Discretion allows it but KISS for Phase 1).
  - Do NOT use `z.string().email()` / URL validators on `baseUrl` — D-17 says inputs are declared but not consumed in Phase 1; runtime URL validation is Phase 3.
  - Do NOT inline the schema in `src/index.ts` — it must be importable by Phase 2/3.
  - Do NOT import from `security-contract.ts` (no coupling needed in Phase 1; Phase 3 might add such coupling later).

**Zod 4 note:** `z.enum([...])` + `.describe(...)` + `.min(1, { message: ... })` are all Zod 4 API. The `message: string` form is Zod 4's new explicit message syntax (Zod 3 used the shorthand `z.string().min(1, 'msg')`). Per RESEARCH.md verification 2026-04-24, the installed version is `zod@^4.0.0` (npm registry 4.3.6). If `npx tsc --noEmit` surfaces a type error on the `{ message: ... }` form, verify `node_modules/zod/package.json` version — it must be 4.x; if it's 3.x somehow, STOP and re-run `npm install` from Plan 01.
