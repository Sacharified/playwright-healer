Write `.gitignore` at the repo root with the following contents:

```
# Dependencies
node_modules/

# Build artifacts (must never exist in this repo — Pitfall 7; guard anyway)
dist/
build/

# Logs
*.log
npm-debug.log*

# Editor / OS
.DS_Store
.vscode/
.idea/

# Environment files (no secrets should ever land in repo)
.env
.env.local
```

**Critical non-obvious requirements:**
  - `noEmit: true` is the single-line guard that enforces D-02 "tsx runs at runtime, no `dist/` drift". Do NOT change.
  - `allowImportingTsExtensions: false` — keeps `import { foo } from './bar.js'` portable across tsx and (hypothetical) tsc compilation. Dispatcher in Plan 03 imports with `.js` extensions; this setting validates that convention.
  - `moduleResolution: bundler` matches the tsx runtime. Do NOT switch to `node16` — D-10 recommends bundler and tsx is esbuild-based.
  - `isolatedModules: true` is a type-system invariant that tsx can compile each file independently — mirrors tsx's actual behavior.
  - `.gitignore` must list `dist/` AND `build/` even though neither should ever exist; future contributors may otherwise accidentally commit them.
  - `.gitignore` must list `.env` — no secrets in repo (SEC-06 defense-in-depth).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Package registry (npmjs.org) → dev machine | Untrusted bytes crossing here are pinned by `package-lock.json` integrity hashes |
| Repo root → CI runner filesystem | `.gitignore` enforces that `node_modules/`, `dist/`, `.env`, logs never enter the repo and thus never enter the runner's workspace |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-08 | Tampering (supply chain — floating version) | `package.json` dependency pinning | mitigate | Exact pins on `@actions/core` (3.0.1), `@actions/github` (9.1.1), SDK (0.2.119), MCP (0.0.70); integrity-locked via `package-lock.json`; SHA-pinning of GitHub Actions handled in Plan 04 (action.yml) and Plan 05/06 (workflow files). Re-verification of GitHub-Actions SHA pins happens in Plan 04's action task via `gh api`. |
| T-dist-drift | Tampering (bundle-drift reintroduction) | `tsconfig.json` + `.gitignore` + `package.json` | mitigate | Triple guard: `tsconfig.json.compilerOptions.noEmit=true`, `.gitignore` excludes `dist/` + `build/`, `package.json` has NO `build` script AND NO `main`/`bin` fields. Pitfall 7. |
</threat_model>
