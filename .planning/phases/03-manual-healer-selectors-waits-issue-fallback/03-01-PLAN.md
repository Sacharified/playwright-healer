**Step A — extend src/shared/config.ts** (insert into the `z.object({…})` body, near the existing CFG-03 block, before the closing brace at line 72):

```typescript
// ── CFG-04: Per-fix-class toggles (Phase 3 ships selectors+waits; assertions+slow toggle-only) ──
enableSelectorFixes:  z.coerce.boolean().default(true),
enableWaitFixes:      z.coerce.boolean().default(true),
enableAssertionFixes: z.coerce.boolean().default(true),
enableSlowFixes:      z.coerce.boolean().default(true),

// ── HEA-02 (D-15): App-supervisor readiness probe ceiling ──
startupTimeoutSeconds: z.coerce.number()
                          .refine((v) => !isNaN(v), { message: 'startup-timeout-seconds must be a valid integer' })
                          .int().min(1).default(120),
```

NOTE on `z.coerce.boolean()`: Zod 4 `coerce.boolean()` treats `""`, `"false"`, `"0"` as false-ish in the standard way; the four toggles use `.default(true)` so an empty INPUT_* (not set) → true, but a literal `"false"` string → false. If the executor finds Zod 4 doesn't behave this way for env strings, fall back to a custom transform: `z.string().default('true').transform(v => v !== 'false')`. Verify with the test cases below.
