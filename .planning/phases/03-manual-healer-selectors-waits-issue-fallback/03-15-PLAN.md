<objective>
Close three medium/low adapter hardening issues that, while not goal-blocking, address security
contract violations and a latent resource leak in the Gemini adapter.

Purpose:
- ME-01: The inline literal `'browser_*'` in gemini.ts line 106 is an MCP tool-name pattern outside
  security-contract.ts, contradicting D-13. Security reviewers cannot audit the full tool surface from
  security-contract.ts alone when discriminant patterns live in adapter code.
- ME-03: The systemPrompt (containing role guardrails, sandbox constraints, forbidden patterns) is
  concatenated into the user-role message. The Google GenAI SDK supports config.systemInstruction for
  true system-role isolation. Mixing security guardrails into user content co-locates them with
  potentially page-injected tool results in later turns (PITFALLS §4 injection concern).
- LO-01: mcpToTool(mcpClient) is called twice per iteration — once in config.tools and once as
  `const callable = mcpToToolFn(mcpClient)`. The @google/genai MCP integration treats mcpToTool as
  a one-time setup. Double-calling per turn can re-initialize transport side effects and leak handles.

Output:
- security-contract.ts: new export `MCP_PLAYWRIGHT_TOOL_PREFIX = 'browser_'`
- gemini.ts: import MCP_PLAYWRIGHT_TOOL_PREFIX; use tool.name.startsWith() for audit check;
  move systemPrompt to config.systemInstruction; initialize mcpToTool once before the loop
</objective>
