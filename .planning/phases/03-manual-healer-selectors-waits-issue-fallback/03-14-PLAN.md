**Change 1 — Remove working-directory directive:**
Delete the line `working-directory: ${{ github.action_path }}` from Step 5.
Composite steps default to `github.workspace` (the consumer checkout root). The start-command
(e.g., `npm run dev`, `python app.py`) must execute from the consumer checkout where
package.json, .env, and application files live — not the action's install directory.

**Change 2 — Exec spawn for correct PID capture (ME-04):**
Change `bash -c "${{ inputs.start-command }}" &` to `bash -c "exec ${{ inputs.start-command }}" &`.
The `exec` builtin replaces the bash shell with the start-command process, so `$!` captures the
application's PID directly. The TypeScript orchestrator's supervisorStop() reads
/tmp/playwright-healer-app-pid and sends SIGTERM to that PID — it must reach the app process.
Without exec, SIGTERM kills the bash wrapper but not the app it spawned.

`npx tsx ${{ github.action_path }}/src/healer/wait-for-ready.ts`.

to GITHUB_WORKSPACE and fail to find the file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pipeline error → GitHub issue body | err.message from internal errors is written into the issue rootCause field |
| start-command input → shell exec | inputs.start-command is exec'd in a bash subshell (consumer-controlled, expected) |
| cwd env var → getExecOutput options | GITHUB_WORKSPACE set by Actions runner infrastructure, not user-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-14-01 | Information Disclosure | HI-03 outer catch — err.message in issue body | mitigate | Truncate message to 1000 chars via `msg.slice(0, 1000)` before embedding in rootCause; pipeline errors from our own code do not embed healerToken (Octokit SDK does not include auth headers in error messages) |
