# Phase 01.1: Multi-Provider Input Surface — Summary

**Phase goal:** Generalize the Anthropic-specific input surface to support Anthropic, Gemini, and Ollama via a `provider` input, with per-provider api-key enforcement so Ollama localhost may run without a key. Adapter code defers to Phase 03.

**Status:** Complete. All 4 success criteria verified at code level + 6 UAT items passed via real GitHub Actions CI run on 2026-04-25.

## What was built

### Input surface (action.yml)
- Renamed `anthropic-api-key` → `api-key`. Dropped `required: true` so Ollama localhost may omit the key.
- Added `provider` (enum `anthropic | gemini | ollama`, default `anthropic`).
- Added `model` (optional string, empty → provider default).
- Added `api-endpoint` (optional string, mainly for Ollama custom host).
- Updated the `INPUT_*` env block: `INPUT_API-KEY`, `INPUT_PROVIDER`, `INPUT_MODEL`, `INPUT_API-ENDPOINT` — preserving the hyphen convention required by `@actions/core` v3.
- Description rewritten to drop `Claude Agent SDK` specific language.

### Validation (src/shared/config.ts)
- Added `ProviderEnum`, exported `Provider` type, and `DEFAULT_MODELS` lookup table:
  - `anthropic` → `claude-sonnet-4-6`
  - `gemini`    → `gemini-2.5-pro`
  - `ollama`    → `llama3.1`
- Renamed `anthropicApiKey` → `apiKey`. Dropped `.min(1)` so the field accepts empty.
- Added `provider`, `model`, `apiEndpoint` fields with safe defaults.
- Appended `.superRefine` enforcing per-provider api-key requirement: empty `apiKey` is allowed only when `provider === 'ollama'`. Error message is masking-safe (no value echo) and uses the camelCase path that 01-VERIFICATION.md assertions rely on.
- Kept `healerToken` and `githubToken` `.min(1)` — always required regardless of provider.

### Dispatcher (src/index.ts)
- Renamed input read for `api-key`. Dropped `required: true` flag (now governed by Zod `superRefine`).
- `core.setSecret(apiKey)` is unconditional — `setSecret('')` is a documented no-op, preserving the branchless D-07 ordering.
- Added `provider`, `model`, `apiEndpoint` to `rawInputs` (read AFTER masking, satisfying D-07 step 3).
- Updated `runDryRun`'s row table:
  - Added `provider`, `model`, `api-endpoint` rows
  - `api-key` cell is provider-aware: `(set — redacted)`, `(empty — allowed for ollama)`, or `(empty)` for anthropic/gemini empty edge case
  - Uses `DEFAULT_MODELS[config.provider]` for the empty-`model` fallback display
- Header comment updated to document the ollama empty-key exception.

### Security contract (src/shared/security-contract.ts)
- Added a doc comment block above `ALLOWED_TOOLS` documenting the per-provider tool-naming translation contract:
  - `anthropic` → identity (canonical `mcp__server__tool` form, double underscore)
  - `gemini`    → `mcp_server_tool` (single underscore, sanitized — per `@google/genai` MCP convention)
  - `ollama`    → native JSON-schema function names via an MCP bridge
- Snapshot JSON values byte-identical (Check 3b passes). Commit carries `Security-Contract-Change: reviewed-by=sacha` trailer per D-13.
